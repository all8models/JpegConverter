# 📦 이미지 압축 웹서비스 프로젝트 계획서

## 1. 프로젝트 개요

**목표**: 사용자가 웹페이지에 이미지를 업로드하면, JPEG 압축 원리를 기반으로 원하는 크기/품질로 압축하여 다운로드할 수 있는 서비스 구축

**핵심 가치**:
- 무료/간편한 이미지 압축
- JPEG 압축 원리(색차 다운샘플링, 양자화)를 활용한 최적화
- 프라이버시 중심 (업로드 파일 서버 미보관)

---

## 2. 기술 스택 선정

| 계층 | 기술 선택 | 이유 |
|------|-----------|------|
| **백엔드** | FastAPI (Python) | 빠른 개발, 이미지 처리 라이브러리 풍부  |
| **이미지 처리** | Pillow + libjpeg | JPEG 압축 핵심 로직 구현 가능, 경량 |
| **비동기 처리** | Celery + Redis | 대용량/다중 파일 처리 시 작업 대기열 필요  |
| **스토리지** | MinIO (또는 S3 호환) | 원본/압축 이미지 임시 저장  |
| **프론트엔드** | React + Vite | 반응형 UI, 드래그 앤 드롭 지원 |
| **컨테이너** | Docker + Docker Compose | 통합 실행 환경, 배포 용이  |

**대안 검토**:
- **완전 클라이언트 측 압축**: `OffscreenCanvas.convertToBlob()` 사용 시 서버 없이도 JPEG 압축 가능 
  - 장점: 서버 비용 0, 프라이버시 완벽 보장
  - 단점: 대용량 이미지(수십 MB) 처리 시 브라우저 성능 제한
- **경량 서버 이미지**: `mochify/mochify-lite` (C++ 기반, JPEG/PNG only, 10MB 제한)

## 3. 시스템 아키텍처

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   React     │────▶│   FastAPI   │────▶│   Celery    │
│   Frontend  │◀────│   (API)     │     │   Worker    │
└─────────────┘     └─────────────┘     ───┬──────────┘
                          │                 │
                          ▼                 ▼
                    ┌─────────────┐    ┌─────────────┐
                    │    Redis    │    │    MinIO    │
                    │  (Broker)   │    │  (Storage)  │
                    └─────────────┘    └─────────────┘
```

**처리 흐름**:
1. 사용자 → 이미지 업로드 (Multipart form)
2. API 서버 → 작업 ID 발급 + Celery task 큐잉
3. Celery Worker → 이미지 압축 처리 (Pillow 활용)
4. MinIO → 압축 결과 저장
5. 사용자 → 작업 ID로 결과 폴링 → 다운로드

## 4. JPEG 압축 구현 상세

### 4.1 압축 파라미터 설계

| 파라미터 | 값 범위 | JPEG 원리 대응 |
|----------|---------|----------------|
| `quality` | 1~100 (기본값 75) | 양자화 테이블 값 조정  |
| `max_width` | 선택 (예: 1920) | 해상도 축소 (추가 압축 효과) |
| `max_height` | 선택 | 종횡비 유지하며 리사이즈 |
| `strip_metadata` | true/false | EXIF 정보 제거로 파일 크기 감소  |
| `format` | jpeg / png | 출력 포맷 선택 |

### 4.2 Python(Pillow) 구현 예시

```python
from PIL import Image
import io

def compress_image(input_stream: bytes, quality: int = 75, max_size: tuple = None) -> bytes:
    """
    JPEG 압축 수행
    - quality: 낮을수록 더 작은 파일 (양자화 강도 증가)
    - max_size: (max_width, max_height) 지정 시 비율 유지 리사이즈
    """
    img = Image.open(io.BytesIO(input_stream))
    
    # RGB 변환 (JPEG은 RGB만 지원)
    if img.mode in ('RGBA', 'P'):
        img = img.convert('RGB')
    
    # 리사이즈 (필요시)
    if max_size:
        img.thumbnail(max_size, Image.Resampling.LANCZOS)
    
    # 압축 저장
    output = io.BytesIO()
    img.save(output, format='JPEG', quality=quality, optimize=True)
    
    return output.getvalue()
```

**압축 원리 매칭** :
- `quality=75` → 양자화 테이블에 75값으로 나눔
- `optimize=True` → 허프만 테이블 최적화 (추가 압축)
- RGB 변환 → YCbCr 색공간 변환과 동일한 효과

### 4.3 품질별 가이드라인 

| 품질 값 | 용도 | 예상 압축률 |
|---------|------|-------------|
| 90-95 | 사진 보관/프로페셔널 | 30-50% |
| 75-85 | 웹 게시 (권장) | 70-80% |
| 60-70 | 썸네일/미리보기 | 85-90% |
| 30-50 | 극단적 압축 | 95%+ |

## 5. API 설계

### 5.1 이미지 압축 요청
```
POST /api/compress
Content-Type: multipart/form-data

Parameters:
  - file: (required) 이미지 파일
  - quality: (optional, 1-100, default=75)
  - max_width: (optional) 최대 너비
  - max_height: (optional) 최대 높이
  
Response:
  {
    "task_id": "abc-123-def",
    "status_url": "/api/status/abc-123-def"
  }
```

### 5.2 상태 확인
```
GET /api/status/{task_id}

Response (진행 중):
  {"status": "processing", "progress": 45}

Response (완료):
  {
    "status": "completed",
    "download_url": "/api/download/abc-123-def",
    "original_size": 4600000,
    "compressed_size": 410000,
    "ratio": 8.9
  }
```

### 5.3 다운로드
```
GET /api/download/{task_id}

Response: 압축된 이미지 바이너리 (Content-Type: image/jpeg)
```

- 다운로드 버튼

### 6.2 클라이언트 측 압축 활용 (선택 사항)

서버 없이도 기본 압축 가능 :
```javascript
async function compressImage(file, quality) {
    const bitmap = await createImageBitmap(file);
    const canvas = new OffscreenCanvas(bitmap.width, bitmap.height);
    const ctx = canvas.getContext('2d');
    ctx.drawImage(bitmap, 0, 0);
    
    const blob = await canvas.convertToBlob({
        type: 'image/jpeg',
        quality: quality  // 0-1 사이 값
    });
    return blob;
}
```

## 8. 보안 및 제한사항

### 8.1 입력 검증
- 최대 파일 크기: 25MB 제한 
- 허용 MIME 타입: `image/jpeg`, `image/png`, `image/webp`
- 업로드 파일은 처리 후 즉시 삭제 (프라이버시)

### 8.2 리소스 제한
- 동시 처리 수: CPU 코어 수 × 2
- 타임아웃: 60초 (대용량 이미지 처리)
