## 1. 이미지 업로드 및 압축 (정상 흐름)

```mermaid
sequenceDiagram
    actor User as 사용자
    participant FE as React 프론트엔드<br/>(localhost:5173)
    participant API as FastAPI 서버<br/>(localhost:8000)
    participant Redis as Redis
    participant Worker as Celery Worker
    participant FS as 로컬 파일 시스템<br/>(/tmp/results/)

    Note over User,FS: ① 이미지 업로드 및 압축 요청

    User->>FE: 이미지 드래그 & 드롭

    FE->>FE: 파일 검증<br/>- MIME 타입 (jpeg/png/webp)<br/>- 크기 (25MB 이하)

    FE->>FE: POST 요청 준비<br/>- quality=75<br/>- format=jpeg

    FE->>API: POST /api/compress (multipart/form-data)
    Note right of API: file + quality + format

    API->>API: 파일 검증 수행<br/>- 크기: 25MB 제한<br/>- MIME 타입 확인

    API->>Worker: compress_image_task.delay(image_bytes, quality)
    Note right of API: Celery 비동기 태스크 실행

    Worker->>Redis: 태스크 수신 (Dequeue)

    API-->>FE: 200 OK { task_id: "abc-123", status_url: "/api/status/abc-123" }

    FE->>FE: 1초 간격 폴링 시작<br/>setInterval(checkStatus, 1000)

    Note over User,FS: ② Worker: 압축 처리

    Worker->>Worker: progress = 10%<br/>이미지 정보 읽기

    Worker->>Redis: update_state(PROCESSING, progress=10)

    Worker->>Worker: progress = 30%<br/>이미지 정보 확인 완료

    Worker->>Redis: update_state(PROCESSING, progress=30)

    Worker->>Worker: Pillow 압축 수행<br/>- RGB 변환<br/>- 리사이즈 (옵션)<br/>- quality 적용<br/>- optimize=True

    Worker->>Worker: progress = 70%<br/>압축 완료

    Worker->>Redis: update_state(PROCESSING, progress=70)

    Worker->>FS: 압축 파일 저장<br/>/{task_id}/compressed.jpg

    Worker->>Worker: progress = 90%<br/>저장 완료<br/>압축률 계산

    Worker-->>Redis: return { original_size, compressed_size, ratio, filename }

    Note right of Redis: 결과 자동 저장<br/>(SUCCESS 상태)

    Note over User,FS: ③ 프론트엔드 상태 폴링

    loop 1초 간격 폴링
        FE->>API: GET /api/status/abc-123

        API->>Redis: AsyncResult(task_id).state 조회

        alt state = PENDING
            Redis-->>API: { status: "pending", progress: 0 }
            API-->>FE: 200 OK { status: "pending" }
            FE->>FE: "대기 중..." 표시

        else state = PROCESSING
            Redis-->>API: { status: "PROCESSING", meta: { progress: 10~90 } }
            API-->>FE: 200 OK { status: "processing", progress: 70 }
            FE->>FE: 진행률 업데이트 (70%)

        else state = SUCCESS
            Redis-->>API: { original_size, compressed_size, ratio, ... }
            API-->>FE: 200 OK { status: "completed", download_url, ... }
            FE->>FE: 폴링 중지<br/>압축 결과 화면 표시
        end
    end

    Note over User,FS: ④ 압축 파일 다운로드

    User->>FE: "압축 파일 다운로드" 버튼 클릭

    FE->>API: GET /api/download/abc-123

    API->>FS: 파일 읽기 /tmp/results/abc-123/compressed.jpg

    FS-->>API: 이미지 바이너리

    API-->>FE: 200 OK (image/jpeg)<br/>Content-Disposition: attachment

    FE->>FE: 브라우저 다운로드 실행
```

## 2. 오류 발생 흐름

```mermaid
sequenceDiagram
    actor User as 사용자
    participant FE as React 프론트엔드
    participant API as FastAPI 서버
    participant Redis as Redis
    participant Worker as Celery Worker
    participant FS as 로컬 파일 시스템

    Note over User,FS: ① 파일 업로드 (파일 크기 초과)

    User->>FE: 이미지 드래그 & 드롭 (30MB)

    FE->>FE: 파일 검증 실패<br/>"파일 크기는 25MB를 초과할 수 없습니다."

    FE-->>User: ❌ 오류 메시지 표시<br/>(업로드 차단, API 호출 안 함)

    Note over User,FS: ② 압축 중 Worker 오류

    User->>FE: 정상 파일 업로드

    FE->>API: POST /api/compress

    API->>Worker: compress_image_task.delay(...)

    API-->>FE: 200 OK { task_id: "def-456" }

    Worker->>Worker: 압축 처리 중<br/>progress = 70%

    Worker->>Worker: ❌ 예외 발생!<br/>(파일 쓰기 실패 등)

    Worker->>Worker: try-except 캐치<br/>traceback 출력

    Worker-->>Redis: update_state(FAILURE, meta={ error: "..." })

    loop 1초 간격 폴링 (최대 3회)
        FE->>API: GET /api/status/def-456

        API->>Redis: AsyncResult 조회

        Redis-->>API: { status: "FAILURE", meta: { error: "..." } }

        API-->>FE: 200 OK { status: "error", message: "파일 쓰기 실패" }

        alt 오류 1회
            FE->>FE: 오류 카운트 = 1<br/>계속 폴링 (일시적 오류 대비)

        else 오류 3회 연속
            FE->>FE: ❌ 폴링 중지
            FE-->>User: ❌ 에러 화면 표시<br/>"파일 쓰기 실패"<br/>+ "다시 시도" 버튼
        end
    end

    User->>FE: "다시 시도" 버튼 클릭
    FE->>FE: 상태 초기화 (idle)<br/>파일 업로드 화면으로 복귀
```

## 7. 핵심 포인트 요약

### 정상 흐름의 4단계
1. **업로드** → React → FastAPI → Celery task 생성
2. **압축** → Worker가 Redis에서 태스크 수신 → Pillow 압축 → 파일 저장
3. **폴링** → React가 1초마다 API로 상태 확인 (10%→30%→70%→90%→100%)
4. **다운로드** → API가 로컬 파일 읽어서 반환 → 브라우저 다운로드

### 오류 처리
- **파일 검증 실패**: API 호출 전 프론트엔드에서 차단
- **Worker 예외**: try-except로 캐치 → FAILURE 상태 → 폴링에서 감지
- **네트워크 오류**: 3회 연속 실패 시 프론트엔드가 에러 표시

### 과거 버그에서 배운 점
- ⚠️ `self.update_state(state="SUCCESS")` → **절대 사용 금지** → return 값이 무시됨
- ⚠️ `catch {}` → **절대 빈 핸들러 금지** → 버그가 숨음
- 💡 Redis 데이터는 `redis-cli GET` 으로 직접 확인하라
