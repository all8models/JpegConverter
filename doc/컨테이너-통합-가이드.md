# 컨테이너 통합 가이드 (5개 → 2개)

## 📌 변경 배경
기존 5개 컨테이너(backend, worker, redis, minio, frontend)를
2개(app, redis)로 통합하여 관리 부담을 줄이고 리소스를 절약합니다.

---

## 📊 변경 전후 비교

| 구분 | 변경 전 (5개) | 변경 후 (2개) |
|------|-------------|-------------|
| backend (FastAPI) | 별도 컨테이너 | ✅ app에 통합 |
| worker (Celery) | 별도 컨테이너 | ✅ app에 통합 (Supervisor) |
| frontend (Nginx/Vite) | 별도 컨테이너 | ✅ app에 통합 |
| minio (오브젝트 스토리지) | 별도 컨테이너 | ❌ 제거 (미사용) |
| redis (메시지 브로커) | 별도 컨테이너 | ✅ 유지 |
| **총계** | **5개** | **2개** |

## 🚀 실행 방법

### 개발 환경
```bash
docker compose up -d --build
# → http://localhost:8000 (FastAPI + 정적파일)
# → http://localhost:5173 (Vite HMR)
# → http://localhost:8000/docs (API 문서)
```

### 운영 환경
```bash
# VERSION 파일 참조
./deploy.sh

# 또는 직접 버전 지정
./deploy.sh 1.1.0

# → http://localhost:80
```

### 롤백
```bash
VERSION_TAG=1.0.0 docker compose -f docker-compose.prod.yml up -d
```

## 🔄 주요 변경 포인트

### 1. Supervisor 도입
- FastAPI, Celery Worker, Vite(dev)를 **단일 프로세스 매니저**로 관리
- 하나라도 죽으면 자동 재시작 (`autorestart=true`)

### 2. FastAPI가 정적 파일 서빙
- Nginx 제거, FastAPI가 React 빌드 결과물 직접 서빙
- SPA fallback 지원 (API가 아닌 모든 경로 → `index.html`)

### 3. MinIO 제거
- `STORAGE_BACKEND=local`이 기본값, MinIO는 실제로 사용되지 않음
- 코드상 MinIO 로직은 남아있지만 컨테이너는 완전 제거

### 4. 버전 관리
- `VERSION` 파일로 버전 추적
- `deploy.sh`로 태깅+빌드+배포+헬스체크 자동화
- `VERSION_TAG` 환경변수로 즉시 롤백 가능
